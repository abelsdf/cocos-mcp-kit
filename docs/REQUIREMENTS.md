# Cocos MCP Kit 开源扩展需求文档

版本：0.6　日期：2026-09-22　状态：纳入 Cocos 官方 CLI 公开路线；首版 P0 范围保持冻结

## 1. 目标与背景

基于 Funplay MCP for Cocos 0.6.3 开发开源 Cocos Creator MCP 扩展，让 AI 客户端能够可靠地查询、构建、修改和验证场景、UI、资源及动画。项目采用独立名称 Cocos MCP Kit，不包含账号认证或用户登录模块。

参考 VberAI Cocos Pro 的公开功能方向，优先实现实际开发所需能力。官网所称“16 个工具、231 项操作”仅作参考，不作为本项目数量或逐项一致的承诺。Unity 官网和本地三张 WebP 图片提供服务器设置、客户端配置、工具管理的交互参考，不代表 Cocos API 或动画体系。

参考来源：

- Funplay 上游：https://github.com/FunplayAI/funplay-cocos-mcp
- Cocos Pro 功能介绍：https://www.vberai.com/game-engines/cocos
- Unity 管理界面参考：https://www.vberai.com/game-engines/unity

- 官网下载包：工作区 `cocos-mcp-v1.8.1-all`，证据与局限见 [Pro 包功能分析](./PRO_PACKAGE_ANALYSIS.md)。模块文件存在不等于功能通过运行验证。

## 3. 范围与环境

本项目首先是 Creator 编辑器扩展，不是完整游戏工程。首轮以 Windows 和 Cocos Creator 3.8.8 为建议验证基线，实施前确认实际测试环境；其他 3.8.x、macOS、Linux 的支持必须以验证结果为准。官方 CLI 后端属于后续可选能力，不改变首版对当前扩展后端的交付要求。

首版交付重点是声明式 UI 构建、模板、知识查询、布局及资源验证、截图验证流程。完整动画编辑、Spine、跨平台发布放在后续阶段。AI 模型与 API 凭据由客户端或用户配置，不默认提供云端生成服务。

## 4. 上游能力与复用原则

源码已包含 HTTP MCP 服务、客户端配置、工具 profiles、场景/组件/资源/预制体操作、脚本执行、截图、诊断和基础动画工具。它们是待验证的基础，不是已通过本项目验收的功能。

复用优先，按需求补齐缺口。当前 Funplay 主要返回 JSON，不支持 GET SSE 长连接；首版不要求服务端持续推送，后续确有长任务需求时再扩展。保留底层脚本执行入口，高频功能提供固定 schema 与结构化结果。

官方 CLI 与 Creator 编辑器扩展作为两个独立后端评估。对外工具不得假定任一后端必然存在；后续通过能力探测报告后端、版本、可用操作和限制。首版继续收敛 JSON UI 构建、模板、验证和截图闭环，只提前设计节点批次事务与只读能力探测，不因官方 CLI 候选功能扩大 P0。

## 6. 构建器数据与调用约定

正式 schema 在实施阶段设计，必须包含：目标场景/父节点、局部节点 ID、节点层级、组件配置、资源引用、事件引用和失败策略。局部 ID 仅用于本次构建的交叉引用，不冒充引擎 UUID。节点批次 DTO 与 JSON UI 构建 schema 分层：前者用于可靠传输/恢复，后者用于面向用户的声明式构建，不能直接暴露或依赖未验证的内部序列化格式。

执行前检查参数、目标、重复局部 ID、组件类型及资源。结果至少返回创建节点映射、成功/失败步骤、警告、保存状态及恢复状态。事件绑定需验证脚本组件与方法；找不到目标不得静默跳过。

“一次调用构建”指减少客户端调用次数，不保证内部只有一次编辑器请求，也不等于自动生成完整游戏。

## 7. 非功能要求

- 可靠性：变更调用按场景协调，避免并发写入互相污染；明确超时、取消及部分成功语义。
- 可维护性：协议、编辑器适配、构建、验证、知识库分层；避免新增巨型通用脚本函数。
- 可观察性：日志包含操作与目标摘要、耗时和错误，限制大正文并过滤凭据；不以返回成功代替产物检查。
- 性能：对较大层级采用限制、分页或差量返回；缓存须在修改后失效。Token 节省通过相同任务的实际输入输出比较，不承诺固定比例。
- 安全：服务默认限本机访问，保留来源校验和项目路径边界；不自动向外发送工程资源；客户端配置写入应可恢复。
- 兼容：核心新增功能提供中文文档，工具 ID 与 schema 保持稳定；平台不支持的能力返回明确错误。
- 来源：所有官方 CLI 衍生能力记录上游仓库、固定提交、版本、许可证和采用方式；不得用浮动 `main` 分支作为可复现验收依据。

## 8. 首版验收场景

1. 在独立测试工程安装扩展，连接一个 MCP 客户端并完成查询、创建、保存、重开。
2. 以 JSON 构建含图片、文字、自定义脚本与按钮事件的 UI，保存后重开，引用正确，点击触发目标方法。
3. 分别生成暂停菜单、设置弹窗和结果弹窗，验证参数化与可编辑性。
4. 使用重复名称、无效资源、无效组件及中途失败输入，验证拒绝行为和新建节点清理。
5. 对越界与引用异常样例执行验证，报告准确定位；对正常样例不产生同类误报。
6. 获取正确的场景和预览图片，记录结构验证结果和视觉检查证据；截图不可用时明确失败。
7. 验证两工程的服务/配置隔离，检查发布包版权声明和更新来源。
8. 使用不同设计分辨率及 Canvas 配置构建 UI，核对视口上下文与越界结果，不混淆屏幕像素和节点坐标。

## 9. 暂不包含

VberAI Studio 云服务、PSD/Figma 全流程转换、AI 美术生成/抠图服务、付费授权解锁、Unity 功能实现、完整 Spine 动画创作、外部导入ExoticAnimation按普通轨道编辑、保证复刻全部宣传231项或目录232项操作。

官方 CLI 的全量复刻、首版强制安装 CLI、首版 upload/publish、首版材质/动画图/光照烘焙，以及未经验证的完全无 GUI Creator 工作流也不在当前首版范围。

## 12. v0.3 运行时核查

## 13. v0.4 官方文档分析后的细化要求

已查阅27个官方手册/API页面并核对本机3.8.8部分公开引擎声明。232项逐项分类为A公开API明确36项、B组合路线115项、C原生适配待核验66项、D替代实现15项。A/B部分依赖C类持久化；这些是工程初评，不是完成数量。证据和逐项路线见[官方文档分析](./COCOS_DOCS_ANALYSIS.md)、[对照矩阵](./reference/PRO_API_FEASIBILITY.md)与[JSON记录](./reference/pro-api-feasibility.json)。

| 关联需求 | 必须遵守的实施与验收边界 |
| --- | --- |
| FR-04/05/13/21 | 在目标Creator“开发者→消息列表”核对场景保存/关闭、资产导入、撤销分组、预制体编辑和动画编辑模式的名称、参数、返回与版本。通用Message API不证明具体消息存在。 |
| FR-05 | 审查Funplay场景/预制体保存中的文件直写回退与JSON编辑入口；未经序列化、meta/UUID、导入及内存状态一致性验证，不作为可靠生产编辑路径。 |
| FR-05/13 | 普通节点操作、关联预制体实例和嵌套实例分别处理；revert不等于全部字段复原。剪贴板优先采用自有格式和引用重映射，原生互通另行核验；这些原生增强不自动进入P0。 |
| FR-14 | 时间统一秒；对外帧号按sample换算，动画事件frame也是秒。sample、clip/state速度、循环模式分别定义；旋转、多通道和离散轨道不得全部使用标量曲线算法。 |
| FR-14 | 支持普通公开轨道模型；外部导入ExoticAnimation不属于该编辑范围。new AnimationClip不等于.anim已保存；原生编辑态和dump格式未确认，先提供自有公开DTO并单独验证保存重开。 |
| FR-10/14 | Widget ALWAYS与位置/尺寸动画冲突须报告；使用ONCE或动画化边距等策略时给出明确行为，不静默覆盖。 |
| FR-15 | socket校验骨骼路径和目标容器；实时、共享缓存等模式分别验证多轨和混合；使用许可兼容样例，不移植商业包资源。 |
| FR-17/18 | 原生Gizmo/网格/图标/观察相机控制尚未确认消息；P0视口上下文以可查询/计算数据验收。独立参考面板使用面板坐标，不冒充Scene原生叠加。 |
| FR-19 | Label描边/阴影按3.8.8实际属性和字体/缓存限制处理；RichText采用独立标记/schema，不照搬全部Label属性。 |
| FR-21/22 | 偏好设置区分默认/全局/本地/项目层，重置移除指定覆盖而不是删除全部用户配置；只承诺已确认的键/分类，编辑器日志与游戏控制台分开。 |
| FR-24/25 | 浏览器无头截图与Creator构建区分；CLI需要图形环境，成功退出码36按官方码表处理。保存/构建时间、缓存、重建和运行就绪状态均须报告。 |

本轮只完成需求与设计依据，不修改功能代码；所有Pro运行测试与本项目新增功能验收保持未完成。完整目录覆盖不要求首版功能全覆盖。

## 14. v0.5 开源项目定位

项目名称调整为 Cocos MCP Kit；本地扩展、包、CLI、面板和配置标识独立于 Funplay。现阶段保留 Funplay MIT 版权及致谢，未配置自有发布渠道前不进行自动发布更新或注册表发布。登录页模板改为暂停菜单，不规划账号认证和用户登录功能。本次改名不改变232项技术可行性分类，运行验收仍未完成。

## 15. v0.6 Cocos 官方 CLI 路线

将公开仓库 `https://github.com/cocos/cocos-cli` 纳入合法来源与工程路线分析，新增 FR-26—FR-31。官方 CLI 提供节点批次序列化、构建生命周期、资源导入 schema、独立 Simulator、高级资源及 3D 生产工具的公开候选路线；这些能力仍须固定提交、核对许可证并在本项目目标环境独立验收。

排期采用“先更新计划、继续收敛 P0、只提前吸收底层架构”的策略：首版前只设计 FR-26 的只读能力探测和 FR-29 的节点事务 DTO/回滚边界，其余进入首版后增强阶段。新增需求不改变八项首版验收场景，也不把官方仓库功能算作本项目已实现。
